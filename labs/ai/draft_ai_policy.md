# ESA Mission Registry Programme — AI Tool Acceptable Use Policy (DRAFT)

**Version:** 0.1 DRAFT  
**Author:** Engineering Manager  
**Date:** 2026-04-15  
**Status:** For team review — not yet approved

---

## Section 1: Purpose

This policy sets out how members of the ESA Mission Registry engineering team may use artificial intelligence (AI) tools, including coding assistants, large language model (LLM) chat interfaces, and AI-powered IDE extensions, in their day-to-day work.

The goal is to allow the team to benefit from AI productivity tools while managing associated risks.

---

## Section 2: Approved Tools

The following tools are approved for use by all engineering team members:

- GitHub Copilot (via existing GitHub Enterprise licence)
- ChatGPT (free tier or personal subscription)
- Any AI extension available in the VS Code marketplace that is free or covered by an existing team licence

Team members may also use any other AI tool they find useful, provided it does not require payment beyond existing team budgets.

---

## Section 3: Prohibited Uses

Team members must not use AI tools to:

- Generate content that is offensive, discriminatory, or harassing
- Attempt to circumvent security controls intentionally
- Share personal data belonging to third parties without consent

---

## Section 4: Code Review

AI-generated code should be reviewed by the developer before it is committed. Developers are responsible for the quality and correctness of any code they submit, regardless of how it was produced.

Where code has been generated with AI assistance, developers are encouraged (but not required) to note this in the commit message or pull request description.

---

## Section 5: Intellectual Property

Developers should be aware that some AI tools may incorporate open source code in their suggestions. If a suggested code block looks like it may have been copied verbatim from a third-party source, the developer should check for licence compatibility before using it.

---

## Section 6: Data Handling

Developers should avoid sharing confidential business data with AI tools where possible. When in doubt, use generic or anonymised examples rather than real data.

The policy does not restrict sharing code with AI tools, as code is considered an internal engineering artefact and not personal data under GDPR.

---

## Section 7: Compliance and Review

This policy will be reviewed annually or when significant changes occur in the AI tool landscape.

Team members who are unsure whether a particular use of an AI tool is permitted should ask their engineering manager.

Non-compliance with this policy may result in disciplinary action in line with the standard HR process.
